# 汽车型式认证证据包审阅与补件平台

用于按车型、配置、法规项目和维护版本组织测试报告、部件清单、软件版本及豁免材料的本地认证工作台。

## 技术栈

- Nuxt 3 + TypeScript
- Nuxt UI
- Pinia
- Nuxt Router
- ofetch
- TanStack Query for Vue

## 主要工作区

- `/`：认证项目列表、关键词/状态/机构/风险筛选和项目统计（风险基于覆盖矩阵的待补 / 版本过期单元格）
- `/projects/new`：建立车型、**多个申报配置**、维护版本和软件版本基线
- `/projects/[id]`：**法规 × 配置覆盖矩阵**、覆盖确认台账、单元格级批量补件、修订链、版本失效范围、批准阻断和审计
- `/regulations`：按法规分类逐配置查看覆盖单元格
- `/supplements`：在覆盖矩阵中勾选待补 / 过期单元格，跨项目批量补件
- `/reminders`：证书和证据到期提醒
- `/audit`：跨项目审批时间线（含覆盖状态迁移）与提交包导出

## 覆盖模型

- 每个项目同时申报多个配置；每个**必选法规 × 配置**是一个覆盖单元格，状态为 `accepted`（已接受）、`pending`（待补）或 `stale`（版本过期）。
- 覆盖确认以台账（`coverage`）为事实来源：审阅接受证据修订时写入接受记录；记录永久保留。
- 软件基线变化时，由申报人指定**受影响配置 × 受影响法规**，仅命中的有效接受记录被置为失效（单元格变为版本过期），旧报告与文件版本仍可在矩阵与修订链中追溯；未命中的配置 / 法规保持已接受。
- 补件不覆盖旧证据：为证据追加一条新修订（修订号递增、软件版本对齐当前基线、状态为待审阅），审阅接受后单元格恢复已接受。
- 批准入口逐格检查：存在任一待补或版本过期的必选单元格时列出对应法规与配置并阻断批准。
- 基线变化、补件、审阅接受 / 拒绝引起的覆盖状态迁移（accepted / pending / stale）写入版本记录与审计。

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:18461`。

## 构建与检查

```bash
npm run typecheck
npm run build
```

项目没有后端服务，使用结构化模拟数据，并通过 Pinia 和浏览器 `localStorage` 持久化车型项目、证据状态、版本和审计记录。ofetch 由本地模拟 fetch 适配器承载，TanStack Query 负责项目索引查询和筛选缓存。
